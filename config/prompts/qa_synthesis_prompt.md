# 问答归档合成 prompt（qa synthesis）

由 `src/scholar/qa.py::build_qa_prompt` 填充占位符后调用。占位符：
`{{QUESTION}}` `{{RESEARCH_INTERESTS}}` `{{EVIDENCE_BLOCK}}` `{{PREVIOUS_ANSWER}}`

---

你在回答一位科研人员对**他自己的文献库**提出的一个具体问题。下面给你的是从这个库里
检索出来的**句级证据**，每条带一个编号（E1、E2……）。请只依据这些证据回答。

## 问题

{{QUESTION}}

## 提问者的研究背景（决定详略取舍，不是让你迎合它）

{{RESEARCH_INTERESTS}}

## 证据

{{EVIDENCE_BLOCK}}

## 上一版答案（如有）

{{PREVIOUS_ANSWER}}

## 铁律

1. **只能用上面列出的证据**。不许写入证据里没有的论文、数字、结论、方法名。
   你自己知道的其他文献一律不许出现——这一页的价值全在于「可追溯到我库里的哪一句」。
2. **引用只写编号**，形如 `["E3", "E7"]`。**绝对不许写 citekey、作者名年份、文献标题**
   当引用标记——引用由程序按编号回译；你若在正文里写出任何 citekey，程序会把它整段剥离，
   不会被保留成引用，并计入违规计数。
3. `points` 与 `caveats` 的**每一条都必须至少有一个证据编号**。凑不出证据就不要写这条。
3b. **不要在正文里写证据编号**（「E1 的流程图说……」「E31 描述的算法」）。编号是本次召回的
   内部序号，读者把这一页摘去写稿之后就完全失去意义。要指某条证据就把它放进该条的
   `evidence` 字段。程序会把正文里漏写的编号回译成 `[@citekey]`、越界的直接删掉，
   但那是兜底，不是让你依赖的写法。
4. **`answer` 是对下面各条的概括**，写 1–3 句，不带编号。它必须是 `points` 支撑得起的结论——
   不许在这里说一句下面没有任何依据的话。**如果证据不足以回答这个问题，`answer` 就要
   直说「库里的证据不足以回答这个问题」**，然后把缺什么写进 `gaps`。
   编一个听起来完整的答案，比承认答不上来危险得多。
5. **`gaps` 写「缺什么类型的证据」，不是泛泛说「研究尚不充分」**。
   例：「上面这 N 条证据里没有一条对 MNAR 检验做过实证功效评估——都是模拟数据」。
   写得越具体越有用。`gaps` 不需要编号。
5b. ⚠️ **`gaps` 只能说「本次证据没有覆盖 X」，绝对不许对整个文献库下断言**。
   「库内没有」「库里几乎完全缺失」「未见相关研究」「该方向尚属空白」这类话
   **一律不许写**——你看到的只是从 2300+ 篇里按这一个问题召回出来的几十条，
   **召回不到 ≠ 库里没有**。实测教训：模型据此写下「库内证据显示这类讨论几乎完全缺失」，
   而库里有一整页 300 行的综述在讲那件事，它的核心文献就躺在你上面的证据表里。
   答错了提问者还能核对；指错方向他不会去核对，因为这一节按设计就没有出处可点。
   合规写法：「本次这批证据里没有一条讨论 X」「上面的证据都没回答 Y」。
6. **`caveats` 放"用这个答案之前必须知道的限制"**：证据来自什么样的数据集/人群/规模，
   有没有外部验证，结论在什么条件下会翻转。宁可多写一条也不要漏——
   这一页的答案很可能被直接摘去写稿。
   但**不要复述 `points` 或 `gaps` 已经说过的内容**：换个说法再说一遍不算"多写一条"，
   只会把真正的限制淹掉（实测 5 条 caveats 里 2 条是复述）。
7. 论断要**具体**：带上条件、数据集、效应量。「多项研究表明该方法有效」是废话；
   「在 MIMIC-IV 上掩码嵌入使 AUROC 提升 0.02，但跨库外验时收益消失」才是论断。
8. **转述并列数字必须完整**。证据里若出现同一组比较的多个数字，转述时要么全部列出，
   要么明确说「其中最弱 X、最强 Y」——不许只挑对论断有利的几个、把最弱的静默丢掉。
   给数值范围时，两端必须是这组数字里真实的最小值和最大值。
9. **不得删除原句的限定语**。证据原句里的「可」「可能」「启发」「值得借鉴」这类推测性措辞
   是作者留下的不确定性标记，转述时必须保留同等强度的语气，
   不能把「可能启发 X」写成「证明了 X」。
10. **域外证据必须标注领域**。证据若来自非临床/非 EHR 领域（图像、文本、通用 ML 基准），
    写进论断时必须显式标注领域来源并注明「尚未在 EHR/临床数据上验证」。
11. 有上一版答案时，把它当草稿修订：保留仍被证据支持的，删掉已被新证据推翻的，
    补上新证据带来的。不要因为某条旧论断这次没检索到证据就删——只在**有反向证据**时才删或改。

    ⚠️ 但**保留一条旧论断时，必须重新给它挂上本次证据里的编号**。
    本次证据是这一轮重新召回的，编号与上一版**完全无关**——照抄上一版的编号一定是错的。
    在本次证据里挂不上任何编号的旧论断，**删掉**，不要留一条没有出处的论断：
    铁律 3 对它同样生效，程序会把它整条丢弃并计入「丢弃 N 条无出处论断」，
    而那个计数本来是用来报"你没按编号引用"的，被正常的修订流程污染之后就失去了意义。

11b. **`answer` 不许断言 `gaps` 里说本次没覆盖到的东西**。这两节自相矛盾是实测发生过的：
    `answer` 写「这是统计上的不可判定性问题」，而同一页的 `gaps` 写「本次证据没有专门
    系统讨论不可识别性这一根本问题」——同一页第一句和边界那一节互相打脸。
    `answer` 不带编号是因为它概括下面各条，**不是**让你在这里说没有出处的话。
    若某个判断本次证据撑不起来，它属于 `gaps`，不属于 `answer`。
12. **JSON 字符串里不许出现半角双引号 `"`**，需要引述时用中文引号「」或直接不加引号。
    （本链路的模型无原生 json_mode，半角双引号会直接把 JSON 打断。）

## 输出格式

只输出一个合法 JSON 对象，第一个字符是 `{`，最后一个字符是 `}`。
不要解释文字，不要 Markdown 代码围栏。

```
{
  "answer": "1-3 句的直接回答；证据不足就直说答不上来。",
  "points": [
    {"text": "带条件与效应量的具体论断。", "evidence": ["E1", "E4"]}
  ],
  "caveats": [
    {"text": "用这个答案之前必须知道的限制。", "evidence": ["E7"]}
  ],
  "gaps": ["本次这批证据里没有覆盖到的具体方面（只说本次证据，不许说整个库有没有）。"]
}
```
