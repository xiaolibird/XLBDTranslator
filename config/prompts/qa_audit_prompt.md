## 铁律

1. **只对比「论断」与「给出的原句」**，不要用你自己的外部知识去判断论断对不对。
   原句本身对不对不是你的事；你只判转述有没有走样。
2. 重点查五件事：
   - **方向/极性**：可证 vs 不可能、增加 vs 减少、成立 vs 不成立、只限 X 也不行 vs 限定在 X 内可证；
   - **限定条件**：是否丢了或改了前提（如「仅 MCAR 且 Y⊥M|X」「在某数据集上」）；
   - **数值与水平**：数字、阈值、水平是否一致（如 1−α vs 1−2α）；
   - **证据类型**：原句是实验观察（某图/某表里的经验结果），论断却写成理论保证（定理、可证明）——判不忠实；
   - **语气强度**：原句说「可能/启发/倾向」，论断写成「证明/保证/一定」。
3. 三种判定：`忠实`（论断与原句的方向、条件、水平、语气都一致）、`不忠实`（上面任一项不符）、
   `无法判断`（原句信息不足以判断，**不要猜**）。
4. `reason` 只写一句话，**指出具体是哪个词、哪个方向或哪个限定条件不符**（忠实时写一句简短依据即可）。
   不要在 reason 里写证据编号或引用标记。
5. **JSON 字符串里不许出现半角双引号 `"`**，需要引述时用中文引号「」。

## 示例（仅演示格式与判法，与上面的待审论断无关）

示例 1（方向被反转 → 不忠实）
论断 [P1]：CP-MDA 类理论结果被限定证明于 P_MAR 或 P_MCAR 分布族内。
所引原句：（可引证据 · 理论结果）Proposition 2.6：即使只限定缺失机制为 MAR 或只限定为 MCAR，条件覆盖仍然无法在无分布假设下达到，同一不可能下界依然成立。
判定：`不忠实`。原句说的是硬度结果（只限 MAR 或 MCAR 也不行，不可能下界依然成立），论断写成了「限定在该族内可证」，方向相反。

示例 2（实验观察被写成理论保证 → 不忠实）
论断 [P2]：CP-MDA 对各种缺失模式都能保证不低于 1−α 的覆盖，与 Theorem 4.3 一致。
所引原句：（可引证据 · 实验结果）图 3a：在多种缺失模式的合成数据上，CP-MDA 的经验覆盖率接近目标水平 1−α。
判定：`不忠实`。原句只是图 3a 的实验观察，不是定理；论断写成了「保证」，还把水平 1−α 与 Theorem 4.3 的 1−2α 混为一谈。

示例 3（忠实）
论断 [P3]：不同医院里 GCS 的缺失率差异极大，一家约 0.46%，另一家约 27.57%。
所引原句：（可引证据 · 实证）Table S5：GCS 缺失率两家医院分别为 0.46% 与 27.57%。
判定：`忠实`。两个数字与对象都与原句一致，没有增删限定条件。

## 输出格式

只输出一个合法 JSON 对象，第一个字符是 `{`，最后一个字符是 `}`。不要解释文字，不要代码围栏。
每个待审论断各出一项，`id` 与上面的 id 一一对应（如 P1、C2）。

```
{
  "audits": [
    {"id": "P1", "verdict": "忠实", "reason": "一句话依据"},
    {"id": "P2", "verdict": "不忠实", "reason": "指出哪个词/方向/限定条件不符"},
    {"id": "C1", "verdict": "无法判断", "reason": "原句缺少 X，无从核对"}
  ]
}
```
