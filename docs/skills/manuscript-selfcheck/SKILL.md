# 稿件对抗性自查（manuscript-selfcheck）

出处：DynaGraph 撤稿案的失败模式反推。那篇的一句话死因是**「正文叙事跑在图表证据前面」**
——本清单的每一道门都对应一个真实翻车点（案例见文末 few-shot，全部出自本库审查实录）。
姊妹 skill：`paper-audit`（审别人的论文用那个；本 skill 是把同一把刀对准自己）。

## 使用方式

1. 拿到稿件（md/tex/docx 均可；docx 先 `pandoc -t markdown` 转出文本层，**图表数字仍须
   人眼对照原图**）；
2. 主 agent 逐门执行下面 15 道硬门，产出核查报告表：`门 | 位置 | 状态(✓/✗/N.A.) | 证据`；
3. **对抗轮（推荐，对应重要投稿必做）**：spawn 一个 subagent，指令只有一条——
   「逐条尝试**反驳**这篇稿件的每个数字宣称与每处图文对应，拿出复算过程」；主 agent 裁决。
   生成者与找茬者不能是同一个上下文（自己核自己会顺着写作时的思路滑过去）；
4. 任何硬门 ✗ 未修复不投稿。修复后**重跑全部 15 门**（改稿会引入新的不一致——实测
   PRIME 那种"标题与正文相反"就是多轮改稿后残留的）。

## 15 道硬门（每道给检查法）

**G1 · 样本量加总**。流程图/各亚组样本数相加 == 文中每一处总数。
检查法：把全文所有样本量数字抽出来列表，逐对加法验证；流程图的数字**看图**，别信文本层。

**G2 · 比例逻辑**。「至少其一」≥ max(单项)；各互斥类相加 ≤ 100%；分母变化处显式说明。

**G3 · 参数全篇一致**。窗口/间隔/阈值/轮数等每个参数，grep 出**全部**提法逐一对照：
```bash
grep -n "hour\|window\|epoch\|threshold\|间隔\|窗" manuscript.md
```
同一参数出现两个值 = ✗（哪怕一处在摘要一处在方法）。

**G4 · 摘要强度 == 正文口径**。摘要里每个宣称（"consistently/首个/最优"）都要能在正文
找到同强度支撑；正文写"from 40% onward"摘要就不许写"across most levels"。
检查法：把摘要拆成单句，逐句标注正文出处页/节。

**G5 · 效应量双口径**。每个"提升 X%"写成「+a.b 个百分点（相对 +c.d%）」双口径；
检查法：对每个提升宣称重算 `pp = a−b` 与 `rel = (a−b)/b`，与文中数字对号。
基准也要点名：是对"全局最强基线"还是"该档位最强基线"。

**G6 · 图文互证**。正文点名的每个变量在图/表中存在；引述的每个图内数值与图上标注一致；
多面板数值不得雷同得不自然（不同数据集逐位相同 = 立即回查生成脚本）。
**流程图/示意图同样要查**——CONSORT 式队列流程图里的 train/test 数字必须与正文的划分声明
一致（实测某 Sci Rep 论文流程图写着外部验证集被 80/20 切分，正文却四处声称"从未训练"）。

**G7 · 标题-首句-结论同向**。每个小节的标题、首句、末句三者方向一致。
多轮改稿后最易残留反向标题——逐节人工过一遍，这条没有自动化捷径。

**G8 · 引用回对**。每个 [n]/[@key] 翻到文献表核对真实标题是否支撑该处论断；
同一条目多处使用时每处语境单独核；转述他人方法的关键词（transformer/ODE/对比学习…）
与被引论文标题/摘要不得矛盾。

**G9 · 公式符号表**。列出全部符号：一符一义、无跨式撞名、总损失系数不与分项复用、
每个矩阵乘法两侧形状写出来走一遍量纲。

**G10 · 加粗审计**。结果表每列自己重算 argmax/argmin，与加粗位逐一比；
禁止整行加粗（会掩盖单项失利——失利项如实不加粗并在正文承认）。

**G11 · 消融增益 vs 方差**。被宣称为核心贡献的每个模块：消融增益必须大于该指标的
折间标准差，否则要么补显著性检验、要么降级措辞。显著性方法写明（检验类型、单位、
多重比较校正）；**种子方差不能冒充抽样不确定性**——用患者级 bootstrap。

**G12 · 宣称-实验对表**。全文每个量化宣称（含时延/内存/参数量）建一张
「宣称 → 支撑实验/表格」对照表，找不到落点的宣称删除或补实验。

**G13 · Code/Data availability**。显式一节（或脚注），有仓库给完整 URL 并在投稿前
`git ls-remote` 验活性；数据受限就写申请路径。**没有也要写"未公开"**，不许沉默。
两条实测教训：(a) **校样阶段务必把匿名评审链接换成正式仓库**——某 Sci Rep 论文发表版留着
`anony10subm/...`（404），而作者真实仓库其实存在；(b) `requirements.txt` 不许出现
Python 标准库（`re`/`csv`/`json`/`argparse`），否则 `pip install -r` 第一步即失败，
等于宣告该文件从未被第三方跑过。

**G14 · 限定词审计**。每处"first/novel/据我们所知"：检索一轮近 18 个月文献后仍成立才保留，
保留时必须带"to the best of our knowledge"级限定。

**G15 · 改稿一致性（换指标/换叙事/换投时必查）**。若审稿意见要求补新指标或重组叙事：
新指标**必须回代码里加实现重跑**，不许从旧数字换算或手工造表（实测某撤稿论文换刊时把
Balanced Accuracy 列替换成 AUROC/AUPRC，而其公开代码里这两个指标零实现，事后被考古证伪）；
图表若改形态（箱线图→带数值柱状图）必须重新生成而非誊抄；跨论文复用素材时清理表注残留
（实测某论文因复制粘贴而声明了一个自己根本没做的外部验证实验）。**改稿是错误引入的高发期**
——DynaGraph 的 arXiv 前身粗糙但真实，致命问题全部诞生于冲刺顶刊的那一轮改写。

## Few-shot：每道门对应的真实翻车案例

| 门 | 真实案例（如果作者投稿前跑过这一条，就不会…） |
|---|---|
| G1 | DynaGraph：摘要 40,856 vs 成分和 54,090，两种算法都还原不出（撤稿五类问题之一）；Zink (Nature Health)：Fig 1b 的 80,610 vs 正文 93,593——**顶刊论文同样中招** |
| G2 | DynaGraph：「至少一种并发症 16.00%」< 单项房颤 28.49% |
| G3 | DynaGraph：3h 间隔两见、4h 窗四见以上，正是撤稿声明点名的 inconsistencies in reported time intervals |
| G4 | TRIDENT (BRACIS)：摘要 consistently outperforms，实际 0%/20% 输给 LightGBM——审稿人一眼即见的落差 |
| G5 | FITEL (Pattern Recognition)：「gains of 0.7%」实为 +0.57 个百分点，读者极易误读成百分点；PRIME (JCST)：「超过 26.0%」复算只有 25.9%、「6.1%」复算 6.5%——两处方向相反，说明连作者自己都没统一复算流程；TRIDENT：「3.4% absolute」是对全局最强基线而非该档最强（对后者只有 2.50pp） |
| G6 | DynaGraph：正文三处大谈 creatinine 而图中节点清单没有它；Fig 4 三面板消融掉幅逐位相同且与正文数字冲突 |
| G7 | PRIME：小节标题「Better on Lower Observation Rate」vs 正文「improvements with higher observation rates」——多轮改稿的典型残留 |
| G8 | DynaGraph：CLOCS[32] 实指胸片放射组学论文；STraTS[33] 被写成 neural ODE 而其标题自带 transformer——后者稿件内部即可自查出来 |
| G9 | DynaGraph：Eq 1 量纲不成立、Eq 20 漏 α 且 λ/μ 撞名——撤稿声明点名的 incorrect equations or missing notations |
| G10 | DySurv (JAMIA)：0.319 被加粗为最优而 CoxTime 0.310 更好；整行加粗掩盖 IBLL 单项失利——同组两年后即出撤稿，加粗偏置是最早的可见苗头 |
| G11 | FITEL：核心模块 DFI 消融增益 0.83pp < 折间标准差 ±1.42 且无检验，仍作为主要贡献宣称；PRIME：损失项消融差异 0.003–0.011 < 标准差 0.009–0.014 却断言"移除任一都退化" |
| G12 | DynaGraph：13ms 推理时延两处引用、零实验支撑 |
| G13 | 实测连续三篇论文的脚本草稿全部漏检 Code availability（其中两篇有公开仓库）——该声明排版上紧挨参考文献、离方法节最远，人和模型都容易漏；FITEL 则是真的没有代码，一篇方法论文因此不可复现 |
| G14 | TRIDENT/PRIME/FITEL 三篇全都有"first/novel"式宣称,其中 FITEL 的"首个端到端联合特征选择与 LLM 表格学习"检索后即可找到近邻工作 |
| G15 | DynaGraph：arXiv 前身用 BA/F1/Sens，投 npj 时把 BA 整列换成 AUROC/AUPRC，而公开代码里这两个指标零实现；同时消融图从无数值箱线图改成带数值柱状图，才出现三面板逐位相同。**F1/Sens 两列在两版逐位相同**——同一批实验、新数字凭空而来 |

## 报告模板

```markdown
# 自查报告：<稿件名> @ <commit/日期>
| 门 | 位置 | 状态 | 证据/复算 |
|---|---|---|---|
| G1 | Fig.1 vs §2.1 | ✓ | 8731+1390=10121 == 文中总数 |
| G5 | 摘要第3句 | ✗ | 写"提升3.1%"，实为 +1.12pp（相对+3.1%），需改双口径 |
...
硬门未过：G5, G7 → 修复后重跑全部 15 门。
对抗轮裁决记录：<subagent 提出 N 条，采纳 M 条，驳回理由...>
```
