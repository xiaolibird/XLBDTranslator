# 生成侧 bench 基线（2026-08-27）

日期：2026-08-27
状态：**基线 v4**（v1 的 100% 虚高、v2/v3 判据仍有洞，三轮对抗审核后定稿）
脚本：`scripts/gen_bench.py`（零 LLM 成本，只审计已落盘页面）
有效性锚：`test_gen_bench.py`（33）+ `test_grounding.py`（14）+ `test_gen_bench_frozen.py`（4，冻结页面）
上游方案：`rag_verification_plan_2026-08.md` 的 P0

## 起因

`rag_bench.py` 只测检索排序（hit@k / nDCG@10 / MRR），**nDCG@10 之后链路上发生的
一切没有任何量化基线**。而现有防线校验的是编号合法性不是内容一致性——`qa.py:783`
自己写着「防线保证 citekey 与原句真实存在，不保证转述没有失真」。

不先补这个基线，验证器（P1/P2）做完也无法证明有没有用，那就是复现被精读的
CRITIC-RAG 那篇最大的方法学毛病：单点数字、无方差、无显著性检验，-0.003 的差异
也拿来给模块重要性排序。

v3 相对 v2 的判据变化（全部来自第一轮对抗审核的实测，逐条零代价或净收益）：

1. ~~中文数字加量词后瞻~~ → **第二轮后整个删除**。加了后瞻仍是「1 个数字换 13 个

2. **百倍换算改 XOR**。`if xp or yp` → `if xp != yp`。两方都带 % 时做换算等于放过
   `0.5%` 抄成 `50%` 这类量级错——正是本判据自称要抓的第一类失真。实测零代价。
3. **匹配池砍到只剩「原句 + 标题」**，删掉 citekey、发表年份、出处行。实测：

   51/455 → 122/455；出处文件名 `科研札记_2023-01.md` 还给出月份值 1）。
   **零收益、可测代价。**
4. **前置字母类**：`smajlović2026Secure` 的 `ć` 挡不住 ASCII 类，`2026` 进入匹配后
   被后置 `(?![A-Z])` 截断成 `202` 塞进池子（真实页面 3 次）。⚠️ 第一版修法写成
   连续码位区段 `À-ɏ`，而 **U+00C0–U+024F 里装着 `×`(U+00D7) 与 `÷`(U+00F7)**，

   发生，2 个数字，主指标无感）。v4 改成显式列出各字母块并跳过 ×÷ 所在空隙，

5. **`derived` 与接地并行判定**：一个跟着「个百分点」的数若逐字就在证据里，它是

   四象限上**逐格等价**，本身不提供新保护；派生量 7→9 的真实原因是**匹配池收窄**

### ⚠️ 修复过程中我自己制造的一个 23 个百分点的回归

## v2 的四个洞（第一轮对抗审核发现，已全部修复）

首版报的「584/584 = 100% 接地」**是虚高的**。5 个 subagent 的对抗审核在判据里找出
四个洞（全部有实测反例，修复见 `src/scholar/grounding.py` 的注释）：

1. **无边界子串匹配**。判据是 `v in pool_flat`，且 pool 先被去掉逗号空格。于是
   「AUC 达到 0.85」被证据「AUC 为 0.853」判接地；「共 48 个中心」被「始于 1948 年」
   判接地；证据「n=150,753 126,804名患者」被压成 `…150753126804名…` 凭空造出新数字。
   改成 token 相等匹配。
2. **百倍换算无条件展开**。每个数字都加 ×100 与 ÷100 变体再求交集，等价类被传递
   放大：「共 5 个中心」被证据「p = 0.05」判接地。改成**至少一方带 %** 才允许换算。
3. **派生检查排在接地检查之后**。于是派生量只要被池中任何碎片蒙对就进不了 derived
   档——「相差超过 20 倍」被 citekey `minoccheri2025Supervised` 的年份片段接地。
   顺序对调后派生量从 7 涨到 10。
4. **出处行号进了匹配池**。`meta` 形如 `· 科研札记_2023-01.md:944`，那个 944 是札记
   文件行号。线上真实发生：qa 页「值超出 3 个 IQR」的 3 全库唯一只靠 `.md:NNN` 接地。

修复过程本身又暴露两个**反向**缺陷（收紧过头造出的假失真，一并修了）：

- `(?![A-Za-z])` 为挡 `4CE` 这类专名，连 `48h`/`5mg` 这类**数字+小写单位**一起挡了。
  证据原句「约 48h」、论断「约 48 小时」被判未接地。改成只排大写字母。
- **中文数字未归一**。证据「值在**三个** IQR 之外」、论断「超出 3 个 IQR」是同一件
  事。新增 `cn_number()` 覆盖 0–999 的常见写法。

数字总数从 591 降到 542，是因为 `COVID-19`/`GPT-4` 里的专名碎片不再被当成数量
（新增 `(?<!\d)(?<![A-Za-z])(?<![A-Za-z]-)` 前置断言）。

**v2 的 2 条报警**：一条是真失真（论断写的 150,753 / 126,804 在它所引 4 篇文献的
证据里都不存在）；一条是边界情况（证据说「可得率近 100%」，论断转述成「缺失接近 0」
——语义对，但做了一次换算，池里没有独立的 0）。后者报出来是正确行为：bench 不该
自作主张判定「可得 100%」等价于「缺失 0」。

## ⚠️ 这个 100% 该怎么读

**它只覆盖 31.2% 的论断。**

| | 条数 | 占比 |
|---|---:|---:|
| 含数字、被本 bench 实际检验 | 142 | 31.2% |
| 不含数字、**一个字都没测到** | 313 | 68.8% |

纯定性论断（"作者认为 X 不足以处理 Y"）本 bench 完全无能为力——数字回对抓不了
措辞失真、立场反转、因果方向倒置。**这 313 条正是 P1 第二层（LLM 蕴含判定）唯一
该花钱的地方**，也说明第二层不是可选项而是必需项。

另外两条读法提醒：

- `lexical_overlap` 是**弱信号，单独不可判定**。转述本就会换词，低覆盖不等于失真。
  只看它的分布漂移——改 prompt 或换模型后整体下移，值得回头看。
- `derived`（派生量）**不计入分母但也不静默豁免**。这 7 个是论断在证据数字上做
  算术得出的比值，按定义不在原句里。抽查了能验证的 5 个：201k/23k≈8.7、
  40/15≈2.7、88.3/3.8≈23、1715/768≈2.2、PT 78/92 差 14 个百分点——**算术全对**。
  但算错的派生数字正是该抓的，所以它们留在 `--detail` 里供抽查。

## 首跑暴露的两个真 bug（都已修）

### 1. 重复 citekey 时原句挂错文献

qa 页 28 条证据只有 15 篇，即同一 citekey 有多条证据。首版用
`list(evidence)[-1]` 找"最近一条证据"给续行（标题/原句）归属——但 `setdefault`
碰到已存在的 key 不改插入顺序，"最后一个 key" 根本不是刚匹配到的那条，于是原句被
挂到别的文献名下。

后果：qa 页词面覆盖 **0.227**（topics 页是 0.5–0.7）、接地率**假跌到 43%**。
修复后为 0.587 / 100%。

这个 bug 只在"证据数 > 论文数"的页面上暴露，topics 页 60 条/60 篇一一对应，
永远测不出来。回归锚：`test_repeated_citekey_keeps_quotes_on_the_right_paper`。

### 2. 数字抽取的两处误伤

- **`4CE` 的 `4`**：4CE 是联盟名（Consortium for Clinical Characterization of
  COVID-19 by EHR），不是数量。修法是数字后加 `(?![A-Za-z])`。
- **`241，` 被当成千分位**：`_norm` 的 NFKC 把中文逗号归一成半角，宽松的
  `[\d,]*` 于是把「相加为241，与摘要」读成一个千分位数字 `241,`。修法是千分位
  必须严格匹配 `,\d{3}`。

## 有效性证明：先证伪，满分才算数

一个永远报满分的指标等于没有指标。`test/test_gen_bench.py` 的断言分三组：

**必须抓到（注入已知失真）**
- 抄错量级：证据 0.06 → 论断 0.6
- 张冠李戴：0.488 是 Beta 的数字，论断挂在 Alpha 头上
- 凭空捏造：证据里根本没有 93.7

**必须不误报（合法写法）**
- 百分号互换（证据 0.488 ↔ 论断 48.8%）
- 千分位（17,775 ↔ 17775）
- 证据编号 E2 不是数字事实
- 专名里的数字（4CE）
- 中文逗号不是千分位
- 元数字豁免（"这 60 条证据"来自页面元信息）
- 批注区不参与评测（拿用户的话去考模型是错的）

**分类正确**
- 派生量进 `derived` 而非 `ungrounded`，且仍出现在明细里
- 逐字接地的数字**不因带派生标记而被移出分母**

**两轮对抗审核后补的守卫**（每一条都对应一个真实发生过的事故）
- 紧邻中文的数字必须抽得出（`共60条` / `缺失率60%`）—— 守整片失效
- 一段密集中文段落的抽取产出量下界 —— 守「判据整体变严导致大面积漏抽」
- 中文数字必须带量词（挡「一致」「十分」「两者」）
- 两方都带 % 时不许百倍换算（挡 `0.5%` 抄成 `50%`）
- 非 ASCII 作者名不漏出截断数字（`smajlović2026Secure`）
- 匹配池只有原句+标题（citekey/年份/出处不进池）
- 行号不进池

这条纪律有来历：`rag_bench` 的 acronym case 集就是因为"9 条 case 全大写、照样
满分"而漏掉小写缩写失明，同一个坑连踩两次（见 `oss_alignment_audit_2026-08.md`
⚠️-2）。先证明能抓，满分才有意义。

## 交叉校验（P1 第一层落地后新增）

生产链路（`validate_synthesis` / `validate_qa`）在**生成时**也算一遍数字接地并把
计数写进 frontmatter；本脚本是**事后从渲染好的 markdown 反算**的。两条路径独立，
⚠️ **两者不该期望相等**（第一轮对抗审核订正）。有一处口径差异是**结构性不可消除**
的：论断渲染时证据编号已回译成 `[@citekey]`，页面上不再有 E 编号，所以 bench 只能
按 citekey 合池（该 citekey 的**全部**证据行），生产侧按 ref 取池（**只有那一条**）。
bench 的池严格更宽 → 只会更宽松。

正确的不变式是**单向**的：`production_ungrounded >= bench_ungrounded`，
`mismatch < 0` 才是真 bug。

这个差异还有一个后果值得记住：按 citekey 合池会让**张冠李戴**在 bench 侧隐形——
而那正是本 bench 声称能抓的两类失真之一。这类只有生产侧那条防线看得见，
**不要以为 bench 全绿就等于没有**。

首次验证（2026-08-27 重跑 shadow-variable）：生产侧 `numbers_checked: 26`、
`ungrounded_numbers: 0`，本脚本反算同为 26 个数字、0 个未接地，**一致 ✓**。

旧版页面没有这两个字段，当前是 `1/9 页带生产计数`——注意这是"没测过"，不是"没问题"。
页面逐步重新生成后这个分母会自己涨上来。

判据本身在 `src/scholar/grounding.py`，bench 与生产链路共用，
`test_gen_bench.py::test_bench_and_production_share_one_judge` 锁住不许各写一套。

## 通过线

沿用 `rag_bench.py` 的口径：**脚本本身不设通过线**（退出码 0 = 跑完），通过线写在
这里：

- `numeric_rate` **不得低于 0.99**（v4 基线 538/542 = 0.9926）。⚠️ 这条原先写的是「不得低于
  1.0，当前 584 个数字全部接地」——那是照抄 v1 虚高基线的产物，在 v2 写下的那一刻
  就已经被违反了。**一个恒定失败的门槛等于没有门槛。**
- 当前的 3 条报警是**已知且已判读**的：两条在 icu-benchmarks（一条真失真——论断写的
  150,753/126,804 在所引 4 篇文献的证据里都不存在；一条边界——证据说「可得率近 100%」
  论断转述成「缺失接近 0」），一条在 qa 页（「超出 3 个 IQR」vs 证据「三个 IQR」，
  中文数字，删 `cn_number` 的已知代价）。掉到 0.99 以下意味着**新增**了报警，必须逐条看 `--detail` 判明是真失真还是规则该放宽。
- `lexical_overlap` 总体 **不得低于 0.55**（当前 0.625）。这是弱信号，只作分布漂移
  告警，掉下来不等于出错，但值得回头看一眼。
- `dropped_claims` / `invalid_refs` / `stripped_cites` 当前全为 0，**任何非零值都
  要求解释**（`topics.py:801-802` 说的"异常值一眼可见"就是这个意思，现在它有聚合了）。

### ⚠️ 前后对照的正确姿势（这条别搞错）

`rag_bench` 的输入是固定 case 集，每次跑输入相同，改完直接复跑就能比。
**`gen_bench` 不是**——它的输入是**当前落盘的那几页**。页面不重新生成，跑一百遍
数字都不会动。

所以：

```
改检索/阈值/prompt/模型  →  重新生成页面（build_topics.py / ask_notes.py）
                         →  再跑 gen_bench 对照
```

直接跑不重新生成，只会得到一个「毫无变化」的**假安慰**。

推论：**「零 LLM 成本」只对审计动作本身成立**，完整的前后对照仍要付生成成本
（8 个概念页目前需分批跑防订阅触顶）。这也意味着 gen_bench 不适合做高频回归——
它的位置是"每次真正改动生成链路时的验收关"，不是"每次提交都跑一遍的冒烟测试"。
高频那一档由 `test/test_gen_bench.py` 承担（纯离线、零成本、随便跑）。

前后对照贴进对应的决策文档。
